메신저 알림은 많아졌는데, 중요한 것만 골라서 챙기기는 더 어려워졌습니다. 특히 개인 프로젝트나 소규모 팀에서는 “이슈 알림, 긴 대화 요약, 마감 리마인더”가 따로 놀기 쉽죠. 이 글은 **OpenClaw**를 이용해 **Telegram 자동화**를 빠르게 시작하고, 실제로 쓸 수 있는 **AI 비서** 흐름(알림/요약/리마인더)을 한 번에 구성하는 튜토리얼입니다.

## 1) 문제정의: 왜 OpenClaw + Telegram 자동화인가

보통 자동화를 시작하면 봇 API, 서버, 스케줄러, 포맷팅을 각각 붙여야 합니다. 초반에는 돌아가도, 실패했을 때 복구가 어렵고 유지보수가 번거롭습니다.

OpenClaw를 쓰면 장점이 명확합니다.
- 메시지 전송/수정/리액션을 `message` 도구로 일관 처리
- 스케줄 실행(크론)과 작업 로그를 한 흐름으로 관리
- 요약/분류 같은 AI 작업을 같은 파이프라인에 결합

즉, “메신저 자동화 + AI 처리 + 운영 복구”를 분리하지 않고 한 덩어리로 가져갈 수 있습니다.

## 2) 최소 셋업

아래는 가장 단순한 시작점입니다.

### (1) 작업 디렉터리 준비
```bash
cd /Users/tofu/blog
mkdir -p scripts logs
```

### (2) Telegram 전송 테스트
OpenClaw에서 메시지 도구가 연결되어 있다면, 먼저 본인 채팅으로 테스트합니다.

```json
{
  "action": "send",
  "channel": "telegram",
  "target": "<chat_id>",
  "message": "✅ OpenClaw Telegram 자동화 테스트"
}
```

여기서 `<chat_id>`는 본인/대상 채팅 ID입니다. 처음에는 반드시 개인 테스트 채팅으로 확인하세요.

### (3) 크론 작업 등록 예시
매일 오전 9시에 요약을 보내는 형태를 가정하면:

```cron
0 9 * * * /usr/bin/env zsh -lc 'cd /Users/tofu/blog && ./scripts/daily-brief.sh >> ./logs/daily-brief.log 2>&1'
```

## 3) 알림/요약/리마인더 시나리오

### 시나리오 A: 알림 (이벤트 즉시 전달)
- 트리거: 배포 실패, 결제 오류, 중요 폼 제출
- 동작: 핵심 필드만 추려 Telegram으로 즉시 전송

메시지 예시:
- `[ALERT] 결제 실패 3건 감지`
- `서비스: checkout-api`
- `최근 오류코드: E502`

노이즈를 줄이려면 “동일 오류 10분 내 1회” 같은 중복 억제 규칙을 두는 게 좋습니다.

### 시나리오 B: 요약 (긴 대화/로그 압축)
- 트리거: 하루 1~2회 정시 실행
- 동작: 최근 로그/대화에서 변경점, 미해결 항목, 다음 액션 3개를 추출

요약 템플릿 예시:
1. 오늘의 핵심 이슈 2건
2. 해결 완료 3건
3. 내일 액션 아이템 3개

요약은 길게 쓰기보다 “지금 결정할 것” 중심이 효율적입니다.

### 시나리오 C: 리마인더 (놓치기 쉬운 마감 방지)
- 트리거: 일정 D-1, D-day 오전
- 동작: 담당자/항목/마감시각을 고정 포맷으로 전송

예시 메시지:
`⏰ [리마인더] 17:00 블로그 발행 마감 (담당: 동욱)`

리마인더는 “시간 + 액션”이 한 줄에 보여야 실제 행동으로 이어집니다.

## 4) 실패 시 복구 방법

자동화는 실패를 전제로 설계해야 합니다. 최소한 아래 4가지는 넣어두세요.

1. **로그 분리**: `logs/alert.log`, `logs/summary.log`처럼 작업별 파일 분리
2. **재시도 정책**: Telegram 전송 실패 시 3회 재시도(지수 백오프)
3. **멱등성 키**: 동일 이벤트 ID는 한 번만 전송
4. **헬스 체크 메시지**: 하루 1회 “파이프라인 정상” 신호 전송

실패 복구용 점검 명령 예시:
```bash
cd /Users/tofu/blog
tail -n 200 logs/daily-brief.log
grep -i "error\|failed" logs/*.log
```

문제가 생기면 “입력 데이터 문제인지, 전송 채널 문제인지, 스케줄 문제인지”를 먼저 분리하세요. 이 순서만 지켜도 복구 시간이 크게 줄어듭니다.

---

정리하면, **OpenClaw** 기반 **Telegram 자동화**는 “알림은 빠르게, 요약은 짧게, 리마인더는 행동 중심”으로 설계할 때 가장 강력합니다. 처음부터 거창하게 만들기보다, 단일 알림 1개 → 일일 요약 1개 → 리마인더 1개 순서로 확장해 보세요. 작은 자동화 3개만 제대로 돌아가도, 체감 생산성은 확실히 달라집니다.
