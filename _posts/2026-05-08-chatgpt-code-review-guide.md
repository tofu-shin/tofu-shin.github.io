코드리뷰를 ChatGPT에 맡기면 빨라지긴 하는데, 결과 품질이 들쑥날쑥하다고 느끼는 경우가 많다. 핵심은 모델 성능보다 **요청 방식**이다. 같은 코드라도 어떻게 질문하느냐에 따라 “겉핥기 코멘트”가 나오기도 하고, 바로 반영 가능한 개선안이 나오기도 한다.

## 1) 나쁜 요청 예시: 왜 실패할까?

### 실패 사례 1: 맥락 없는 한 줄 요청
“이 코드 리뷰해줘.”

문제는 코드의 목적, 실행 환경, 우선순위가 전혀 없다는 점이다. 이 경우 ChatGPT는 일반론(가독성, 네이밍, 주석 추가 등) 위주로 답하고, 실제 장애를 막는 리뷰로 이어지기 어렵다. 특히 성능 병목이나 동시성 이슈처럼 맥락 의존적인 문제는 거의 못 잡는다.

### 실패 사례 2: 너무 큰 덩어리 붙여넣기
“프로젝트 전체 붙여넣었으니 문제점 다 찾아줘.”

수천 줄을 한 번에 던지면 답변이 요약 중심으로 축소된다. 중요한 부분이 누락되고, 잘못된 가정이 섞일 확률도 올라간다. 결국 “많이 받았는데 쓸 건 적은” AI 코드리뷰가 된다.

## 2) 좋은 요청 예시: 이렇게 바꾸면 달라진다

### 성공 사례 1: 역할 + 목표 + 제약 명시
“너는 시니어 백엔드 리뷰어야. 아래 PR은 결제 API 타임아웃 핫픽스야. 
환경: Node.js 20, PostgreSQL, 트래픽 피크 2k rps.
우선순위: 1) 장애 위험 2) 성능 3) 스타일.
반드시 재현 시나리오와 수정 코드(diff 형태)까지 제안해줘.”

이렇게 주면 ChatGPT 코드리뷰가 ‘취향 피드백’이 아니라 ‘운영 리스크 점검’으로 바뀐다. 리뷰 결과도 즉시 실행 가능한 액션 아이템 형태로 나온다.

### 성공 사례 2: 범위 분할 + 정답 포맷 지정
“아래 함수 120줄만 리뷰해줘.
출력 형식:
- Critical/Warning/Nit 분류
- 근거(왜 문제인지)
- 수정 예시 코드
- 테스트 케이스 2개”

범위를 줄이고 포맷을 강제하면 누락이 줄고 비교가 쉬워진다. 여러 함수에 같은 템플릿을 적용하면 팀 내 AI 코드리뷰 품질이 일정해진다.

## 3) 리뷰 품질 높이는 체크리스트

- 코드의 **목적/비즈니스 맥락**을 먼저 적었는가?
- 실행 환경(언어 버전, 프레임워크, DB, 트래픽)을 제공했는가?
- 우선순위(보안, 성능, 안정성, 가독성)를 명확히 했는가?
- 리뷰 범위를 파일/함수 단위로 잘랐는가?
- 출력 형식(심각도, 근거, 수정안, 테스트)을 지정했는가?
- “문제 없음”이 아니라 **반례/실패 시나리오**를 요구했는가?
- 제안 코드에 대해 로컬 테스트/린트로 검증했는가?

이 7가지만 지켜도 개발 생산성이 눈에 띄게 올라간다.

## 4) 재질문 루프: 한 번에 끝내지 말기

좋은 AI 코드리뷰는 1회성 Q&A가 아니라 루프다.

1. 1차 질문: 맥락+범위+포맷으로 리뷰 받기
2. 2차 질문: “가장 위험한 1개만 깊게” 파고들기
3. 3차 질문: 수정안 반영 후 “회귀 위험” 재검토
4. 4차 질문: 테스트 보강(경계값/동시성/실패 케이스)

마지막으로 “이 변경을 배포해도 되는지, 남은 리스크 3개만”을 물으면 의사결정 속도가 빨라진다. 결론적으로 **AI 코드리뷰의 품질은 모델이 아니라 질문 설계에서 결정된다.** ChatGPT를 검색창처럼 쓰지 말고, 리뷰어처럼 일하게 만들어보자.
