AI 자동화가 빨라질수록 사고도 빨라집니다. 문제는 기술 자체보다 운영 습관에서 터집니다. 아래는 실무에서 자주 본 **AI 자동화 보안** 실수 TOP 10입니다. 각 항목마다 위험도와 **예방/탐지/복구**를 붙였으니 체크리스트처럼 활용해 보세요.

## 1) 시스템 프롬프트·API 키를 같은 컨텍스트에 넣기
- **위험도:** 매우 높음
- **예방:** 시스템 지시문, 비밀키, 사용자 입력을 물리적으로 분리(비밀관리 서비스 + 최소 노출)
- **탐지:** 응답/로그에 키 패턴, 내부 지시문 문자열 정규식 스캔
- **복구:** 키 즉시 폐기·재발급, 노출 범위 역추적, 영향 사용자 공지

## 2) 프롬프트 인젝션 방어 없이 외부 문서 요약 자동화
- **위험도:** 매우 높음
- **예방:** 신뢰경계 설정(외부 콘텐츠는 비신뢰), 도구 호출 화이트리스트, 정책 기반 출력 필터
- **탐지:** “이전 지시 무시”류 패턴, 비정상 도구 호출 시도, 권한 상승 요청 알림
- **복구:** 워크플로 일시 중지, 오염된 문서 인덱스 재빌드, 규칙 업데이트

## 3) 과도한 권한 토큰(관리자급)을 자동화 전역에 사용
- **위험도:** 매우 높음
- **예방:** 작업별 단기 토큰, 최소권한 RBAC, 환경별 계정 분리
- **탐지:** 평소보다 넓은 스코프 API 호출, 야간/비정상 IP 접근 경보
- **복구:** 토큰 회수, 권한 재설계, 고위험 액션은 승인 게이트 추가

## 4) 로그에 민감정보를 평문 저장
- **위험도:** 높음
- **예방:** PII/비밀 마스킹, 구조화 로그 필드 분리, 보존기간 최소화
- **탐지:** DLP 룰로 주민번호·카드·키 패턴 탐지, 샘플링 점검
- **복구:** 로그 접근 차단, 삭제/파기 절차 수행, 규제 대응 기록화

## 5) 공개 채널(채팅/이슈)에 내부 데이터 자동 전송
- **위험도:** 높음
- **예방:** 채널 등급화(공개/내부/기밀), 전송 전 분류기·검열기 적용
- **탐지:** 외부 채널 발신 이벤트 모니터링, 첨부파일 DLP 스캔
- **복구:** 게시물 삭제, 공유 링크 만료, 재발방지 룰 즉시 반영

## 6) 테스트/운영 분리 없이 같은 모델·같은 스토리지 사용
- **위험도:** 높음
- **예방:** 프로젝트·버킷·DB를 환경별 완전 분리, 샌드박스 강제
- **탐지:** dev 계정의 prod 리소스 접근 로그, 교차환경 호출 알림
- **복구:** 데이터 경계 재구성, 오염 데이터 격리, 재처리 파이프라인 실행

## 7) 승인 없는 자동 실행(메일 발송, 결제, 배포)
- **위험도:** 높음
- **예방:** 고위험 액션은 Human-in-the-loop, 금액/대상 임계치 설정
- **탐지:** 급증 트래픽, 반복 실패/재시도 폭주, 이상행동 룰
- **복구:** 킬스위치로 즉시 중단, 롤백, 수동 검증 후 단계적 재개

## 8) 모델 출력 검증 부재(JSON 스키마/정책 검증 없음)
- **위험도:** 중간~높음
- **예방:** 스키마 강제, 정책 엔진(허용 명령만), 실패 시 안전 기본값
- **탐지:** 파싱 실패율·정책 위반율 대시보드화
- **복구:** 실패 작업 재큐잉, 잘못 반영된 변경 자동 되돌리기

## 9) 서드파티 플러그인·에이전트 공급망 검증 부족
- **위험도:** 중간~높음
- **예방:** 서명/해시 검증, 버전 고정, 권한·네트워크 샌드박싱
- **탐지:** 신규 버전 동작 편차, 의심 도메인 통신, 무결성 체크 실패
- **복구:** 이전 버전 롤백, 침해 IOC 기반 포렌식, 공급망 정책 강화

## 10) 사고 대응 런북·훈련 부재
- **위험도:** 중간
- **예방:** 운영 보안 관점의 런북(누가/무엇을/언제), 분기별 모의훈련
- **탐지:** MTTD/MTTR 지표 추적, 알림 누락·지연 리포트
- **복구:** 사고 회고(원인/대응/개선), 통제항목 백로그화

### 실무용 30초 체크리스트
1. 비밀정보와 프롬프트를 분리했는가?
2. **프롬프트 인젝션** 대응 규칙과 도구 화이트리스트가 있는가?
3. 민감정보가 로그·공개채널로 새지 않게 막았는가?
4. 고위험 자동 액션에 승인/킬스위치가 있는가?
5. 탐지 지표(MTTD/MTTR, 위반율)를 운영 보안 대시보드에서 보는가?

AI 자동화는 “정확한 모델”보다 “안전한 운영”이 성패를 가릅니다. 오늘 한 가지라도 막으면, 내일 큰 사고 하나를 줄일 수 있습니다.
