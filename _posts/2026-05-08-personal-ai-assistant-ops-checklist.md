개인용 **AI 비서**는 한 번 붙여두면 편하지만, 운영 기준 없이 돌리면 금방 피로해진다. 알림 폭주, 권한 과다, 스케줄 충돌, 로그 누락이 대표적이다. 아래는 실제로 바로 적용할 수 있는 **운영 체크리스트**다. 핵심은 “똑똑한 모델”보다 “지속 가능한 **자동화 관리** 체계”다.

## 1) 보안 체크리스트

- [ ] AI 비서 실행 계정과 개인 메인 계정을 분리했다.
- [ ] 토큰/API 키는 `.env` 또는 시크릿 저장소로 관리하고, 저장소 커밋에서 제외했다.
- [ ] 외부 전송(메일/메신저/게시)은 기본 차단, 허용 작업만 화이트리스트로 열었다.
- [ ] 파일/캘린더/메시지 접근 권한을 “최소 권한”으로 설정했다.
- [ ] 민감 데이터(주민번호, 계좌, 인증코드)는 마스킹 규칙을 적용했다.
- [ ] 원격 접속은 VPN/Tailscale 등 폐쇄 네트워크 우선으로 구성했다.
- [ ] 비상 시 즉시 끊을 수 있는 Kill Switch(토큰 폐기/봇 정지)를 준비했다.

**실무 팁:** 주 1회 “권한 다이어트”를 돌려서, 지난 30일 미사용 권한은 제거한다.

## 2) 알림정책 체크리스트

- [ ] 알림 등급을 3단계(긴급/중요/참고)로 나눴다.
- [ ] 야간 시간(예: 23:00~08:00)은 긴급만 허용했다.
- [ ] 동일 이슈 반복 알림은 묶음(디바운스/스로틀) 처리했다.
- [ ] 실패 알림에는 원인·영향·다음 액션 1개를 포함시켰다.
- [ ] “읽기 확인용 알림”과 “행동 필요 알림” 채널을 분리했다.

**실무 팁:** 알림은 많이 보내는 게 아니라, “지금 내가 뭘 해야 하는지”를 1문장으로 끝내야 한다.

## 3) 스케줄 체크리스트

- [ ] 반복 작업은 heartbeat(느슨한 주기)와 cron(정시 작업)을 구분했다.
- [ ] 외부 API 호출 작업은 분산 실행해 피크 타임을 피했다.
- [ ] 일정 충돌 시 우선순위 규칙(P1>P2>P3)을 문서화했다.
- [ ] 실패 재시도는 즉시 1회 + 지수 백오프로 제한했다.
- [ ] 월 1회 “죽은 자동화”(아무도 안 보는 작업) 정리 시간을 확보했다.

**실무 팁:** 새 자동화는 바로 상시 운영하지 말고, 1주일 그림자 모드(알림만)로 검증 후 승격한다.

## 4) 로그관리 체크리스트

- [ ] 작업 단위마다 실행 시각, 입력, 결과, 실패 원인을 남긴다.
- [ ] 로그는 검색 가능한 형식(JSONL/구조화 텍스트)으로 저장한다.
- [ ] 개인정보/토큰은 저장 전 필터링한다.
- [ ] 에러 패턴 Top 5를 주간 리포트로 자동 집계한다.
- [ ] 보관기간(예: 상세 30일, 요약 180일)을 분리해 운영한다.

**실무 팁:** 로그의 목적은 “기록”이 아니라 “재현”이다. 누가 봐도 다시 따라할 수 있어야 한다.

## 5) 복구플랜 체크리스트

- [ ] 장애 등급(부분 장애/전체 중단)을 정의했다.
- [ ] 장애 시 10분 내 수동 전환 절차를 문서화했다.
- [ ] 백업 대상(프롬프트, 설정, 스케줄, 키 제외 메타데이터)을 지정했다.
- [ ] 주 1회 복구 리허설(테이블탑 테스트)을 수행한다.
- [ ] “마지막 정상 버전”으로 롤백하는 명령/절차를 준비했다.
- [ ] 운영 중지 후 재가동 체크리스트(권한·알림·스케줄 순서)를 갖췄다.

**실무 팁:** 복구 문서는 길수록 실패한다. 장애 문서는 A4 한 장으로 끝내라.

## 오늘 바로 적용할 최소 점검표 (10분)

1. 외부 전송 권한 기본 차단 확인
2. 야간 알림 정책 적용
3. 실패 알림 템플릿(원인/영향/다음 액션) 통일
4. cron 중복 작업 1개 제거
5. 로그에 민감정보 마스킹 규칙 추가
6. Kill Switch 동작 테스트 1회

개인 **AI 비서** 운영의 본질은 모델 성능이 아니라, 사고 없이 오래 굴리는 시스템이다. 이 **운영 체크리스트**를 기준선으로 삼으면 자동화는 부담이 아니라 레버리지가 된다. 결국 좋은 **자동화 관리**는 “적게 놀라고, 빨리 복구하고, 계속 개선하는 것”이다.
